# QIE Sentinel v0.8 — GitHub + Vercel release overlay

**Overlay only:** run `unzip -o` in the existing `/mnt/c/Github/qie-sentinel` repository. No smart contract or private database files included. Creates `site/`, `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, `docs/DEMO.md`, `README-PUBLIC.md`, `.github/workflows/agent-ci.yml`, publication checks.

## What to publish

- GitHub: source repository and `README-PUBLIC.md` (copy to `README.md` after backing up old README).
- Vercel: `site/` only. Static marketing / evidence / simulation UI, no wallet, no API, no secrets.
- Private PC: existing `sentinel-agent/server.py` on PM2 port 8765, SQLite, Foundry keystores.

## `.gitignore` — mandatory before git add

The release does not overwrite your existing ignore file. Add these entries to root `.gitignore` if not already present:

```
__pycache__/
*.pyc
*.db
*.db-*
*.sqlite
*.sqlite3
sentinel-evidence.json
sentinel-chain-payments.json
sentinel-showcase.html
.env
.env.*
!.env.example
.vercel/
node_modules/
lib/
out/
cache/
broadcast/
```

Then inspect paths before publishing. The release includes `scripts/check-publish.sh` which detects suspicious **tracked filenames**, but it cannot audit every secret in file contents.

```bash
git status --short
git ls-files --cached
bash scripts/check-publish.sh
```

If the repository already tracks a secret, add to `.gitignore` is insufficient: `git rm --cached path/to/secret` and rotate the secret. Never publicly push an unreviewed `.env`, private database, keystore, signature or access token.

## GitHub

If no Git remote has been configured, use `gh auth login` and `gh repo create qie-sentinel --public --source=. --remote=origin --push` only **after** privacy review. To use existing repo instead, commit then `git push -u origin main`; do not create a second remote accidentally. See final assistant instructions for a safe check-first sequence.

## Vercel

Connect the repo in Vercel with **Root Directory = site**. Or `cd site && npx vercel && npx vercel --prod`. The Vercel URL is generated by Vercel; do not claim it exists until deployment succeeds.

The public site intentionally does not connect to `127.0.0.1:8765`. This separation protects the private signing and proposal environment.
